# เอกสารข้อกำหนดความต้องการระบบ (Requirements Specification)

## โครงการ AI YouTube Planner
### รุ่น Minimum Viable Product (MVP)

> ระบบวางแผน จัดการ และคิดไอเดียคอนเทนต์ YouTube ด้วยปัญญาประดิษฐ์

---

## 1. บทนำ (Introduction)

### 1.1 ความเป็นมาและวัตถุประสงค์

ผู้สร้างคอนเทนต์ YouTube จำนวนมากประสบปัญหาการวางแผนคอนเทนต์อย่างเป็นระบบ ตั้งแต่การคิดไอเดีย การจัดตารางการผลิต ไปจนถึงการติดตามผลลัพธ์หลังเผยแพร่ โครงการ AI YouTube Planner จึงถูกพัฒนาขึ้นเพื่อเป็นเครื่องมือฟรีที่ช่วยผู้สร้างคอนเทนต์ในทุกขั้นตอนดังกล่าว โดยนำปัญญาประดิษฐ์ (AI) เข้ามาช่วยระดมไอเดียคอนเทนต์ตามทิศทางของช่อง

### 1.2 วัตถุประสงค์ของโครงการ

- เพื่อพัฒนาเครื่องมือช่วยคิดไอเดียคอนเทนต์ YouTube โดยใช้ AI
- เพื่อให้ผู้ใช้สามารถวางแผนและติดตามสถานะการผลิตคอนเทนต์อย่างเป็นระบบ
- เพื่อให้ผู้ใช้สามารถบันทึกและวิเคราะห์ผลลัพธ์หลังเผยแพร่คอนเทนต์ได้
- เพื่อพัฒนาระบบต้นแบบ (MVP) ที่ใช้งานได้จริงโดยไม่มีค่าใช้จ่าย

---

## 2. ขอบเขตของระบบ (Scope)

### 2.1 สิ่งที่รวมอยู่ใน MVP

- ระบบสมัครสมาชิกและเข้าสู่ระบบ 3 ช่องทาง (Email/Password, GitHub, Google)
- ระบบสร้างไอเดียคอนเทนต์อัตโนมัติด้วย AI (Google Gemini API)
- ระบบจัดการไอเดียที่บันทึกไว้ (บันทึก/ลบ/ย้ายเข้าปฏิทิน)
- ระบบวางแผนคอนเทนต์แบบบอร์ดสถานะ (Kanban) และปฏิทินรายเดือน
- ระบบบันทึกรายละเอียดการผลิต (ชื่อคลิปสำรอง, ไอเดียภาพปก, Hook, Call-to-action, ซีรีส์)
- ระบบบันทึกและวิเคราะห์ผลลัพธ์หลังเผยแพร่ (ยอดวิว, CTR, Retention)
- หน้าภาพรวม (Dashboard) แสดงสถิติและกำหนดการที่ใกล้ถึง

### 2.2 สิ่งที่ไม่รวมอยู่ใน MVP (Out of Scope)

- การเชื่อมต่อ YouTube Data API เพื่อดึงสถิติช่องจริงโดยอัตโนมัติ
- การอัปโหลดหรือจัดเก็บไฟล์วิดีโอ/ภาพปกจริง
- ระบบแจ้งเตือนผ่านอีเมลหรือ Push Notification
- ระบบทีม/การทำงานร่วมกันหลายผู้ใช้ในโปรเจกต์เดียวกัน
- การวิเคราะห์คำหลัก (Keyword Research) หรือข้อมูลเทรนด์จากภายนอก

---

## 3. ผู้ใช้งานระบบ (User Role)

ระบบ MVP รองรับผู้ใช้งานประเภทเดียว คือ **"ผู้สร้างคอนเทนต์ (Content Creator)"** ซึ่งเป็นเจ้าของบัญชีและข้อมูลทั้งหมดของตนเอง โดยไม่มีการแบ่งปันข้อมูลระหว่างผู้ใช้ในรุ่น MVP นี้

---

## 4. รายการกรณีการใช้งาน (Use Cases)

| รหัส | Use Case | คำอธิบาย |
|---|---|---|
| UC-01 | สมัครสมาชิก / เข้าสู่ระบบ | ผู้สร้างคอนเทนต์เลือกสมัคร/เข้าสู่ระบบด้วยอีเมล, GitHub หรือ Google |
| UC-02 | สร้างไอเดียคอนเทนต์ด้วย AI | ผู้ใช้ระบุหัวข้อ ระบบเรียก AI คืนไอเดีย 5 รายการให้เลือกบันทึก |
| UC-03 | จัดการไอเดียที่บันทึกไว้ | ผู้ใช้ดู/ลบ/เพิ่มไอเดียที่บันทึกไว้เข้าสู่ปฏิทิน |
| UC-04 | วางแผนและติดตามสถานะคอนเทนต์ | ผู้ใช้สร้าง/แก้ไข/ลบงานคอนเทนต์ และเปลี่ยนสถานะผ่านบอร์ดหรือปฏิทิน |
| UC-05 | บันทึกรายละเอียดก่อนผลิต | ผู้ใช้กรอกชื่อคลิปสำรอง ไอเดียภาพปก Hook และ Call-to-action ต่องานแต่ละชิ้น |
| UC-06 | บันทึกและวิเคราะห์ผลลัพธ์ | ผู้ใช้กรอกยอดวิว/CTR หลังโพสต์ และดูสรุปซีรีส์ที่ทำผลงานดีที่สุด |

## 5. ข้อกำหนดความต้องการเชิงฟังก์ชัน (Functional Requirements)

### Authentication

| รหัส | รายละเอียด Requirement |
|---|---|
| FR-01 | ผู้ใช้สามารถสมัครสมาชิกด้วยอีเมลและรหัสผ่าน (อย่างน้อย 6 ตัวอักษร) ได้ |
| FR-02 | ผู้ใช้สามารถเข้าสู่ระบบด้วยบัญชี GitHub (OAuth) ได้ |
| FR-03 | ผู้ใช้สามารถเข้าสู่ระบบด้วยบัญชี Google (OAuth) ได้ |
| FR-04 | ระบบต้องเข้ารหัสรหัสผ่านด้วย bcrypt ก่อนบันทึกลงฐานข้อมูล ห้ามเก็บเป็นข้อความธรรมดา |
| FR-05 | ผู้ใช้ที่ยังไม่เข้าสู่ระบบต้องถูกนำทางไปหน้า Login โดยอัตโนมัติเมื่อพยายามเข้าถึงหน้าที่ต้องยืนยันตัวตน |

### AI Idea Generation

| รหัส | รายละเอียด Requirement |
|---|---|
| FR-06 | ผู้ใช้สามารถระบุหัวข้อและบริบทของช่อง เพื่อให้ AI สร้างไอเดียคอนเทนต์ได้ |
| FR-07 | ระบบต้องเรียกใช้ Gemini API เพื่อสร้างไอเดียคอนเทนต์อย่างน้อย 5 รายการต่อการร้องขอ 1 ครั้ง |
| FR-08 | หากเรียก AI ไม่สำเร็จเนื่องจากปริมาณการใช้งานสูง ระบบต้องลองเรียกซ้ำอัตโนมัติก่อนแจ้งข้อผิดพลาดแก่ผู้ใช้ |
| FR-09 | ผู้ใช้สามารถบันทึกไอเดียที่ AI สร้างไว้เก็บเป็นรายการส่วนตัวได้ |
| FR-10 | ผู้ใช้สามารถลบไอเดียที่บันทึกไว้ได้ โดยระบบต้องแสดงกล่องยืนยันก่อนลบทุกครั้ง |
| FR-11 | ผู้ใช้สามารถเพิ่มไอเดียที่บันทึกไว้เข้าสู่ปฏิทินคอนเทนต์ได้โดยตรงในคลิกเดียว |

### Content Planning

| รหัส | รายละเอียด Requirement |
|---|---|
| FR-12 | ผู้ใช้สามารถสร้างงานคอนเทนต์ใหม่ได้ด้วยตนเองโดยไม่ต้องผ่าน AI |
| FR-13 | ผู้ใช้สามารถกำหนดสถานะงานคอนเทนต์ได้ 5 ระดับ: ไอเดีย, เขียนสคริปต์, ถ่ายทำ, ตัดต่อ, โพสต์แล้ว |
| FR-14 | ผู้ใช้สามารถกำหนดวันที่นัดหมายเผยแพร่ของแต่ละงานคอนเทนต์ได้ |
| FR-15 | ระบบต้องแสดงงานคอนเทนต์ในรูปแบบบอร์ดสถานะ (Kanban) แยกตามคอลัมน์สถานะทั้ง 5 ระดับ |
| FR-16 | ระบบต้องแสดงงานคอนเทนต์ในรูปแบบปฏิทินรายเดือน พร้อมสลับไปมากับมุมมองบอร์ดได้ |
| FR-17 | ผู้ใช้สามารถกรองรายการงานคอนเทนต์ตามซีรีส์/เพลย์ลิสต์ที่กำหนดเองได้ |
| FR-18 | ผู้ใช้สามารถบันทึกรายละเอียดเสริมของคอนเทนต์ได้ ได้แก่ ชื่อคลิปสำรอง ไอเดียภาพปก Hook เปิดคลิป และ Call-to-action |
| FR-19 | ผู้ใช้สามารถลบงานคอนเทนต์ได้ โดยระบบต้องแสดงกล่องยืนยันก่อนลบทุกครั้ง |

### Results Tracking

| รหัส | รายละเอียด Requirement |
|---|---|
| FR-20 | ผู้ใช้สามารถบันทึกยอดวิวและอัตราการคลิก (CTR) ของคอนเทนต์ที่มีสถานะ "โพสต์แล้ว" ได้ |
| FR-21 | ผู้ใช้สามารถบันทึกบทสรุปผล Retention หรือสิ่งที่เรียนรู้จากคอนเทนต์แต่ละชิ้นได้ |
| FR-22 | ระบบต้องแสดงรายการคอนเทนต์ที่โพสต์แล้วทั้งหมด เรียงลำดับตามยอดวิวจากมากไปน้อย |
| FR-23 | ระบบต้องคำนวณและแสดงซีรีส์ที่มียอดวิวเฉลี่ยต่อคลิปสูงที่สุดให้ผู้ใช้เห็นโดยอัตโนมัติ |

### Dashboard

| รหัส | รายละเอียด Requirement |
|---|---|
| FR-24 | ระบบต้องแสดงภาพรวมจำนวนงานคอนเทนต์แยกตามสถานะทั้ง 5 ระดับ บนหน้า Dashboard |
| FR-25 | ระบบต้องแสดงรายการกำหนดการที่ใกล้ถึง (5 รายการล่าสุด) บนหน้า Dashboard |

## 6. ข้อกำหนดความต้องการที่ไม่ใช่เชิงฟังก์ชัน (Non-Functional Requirements)

| รหัส | หมวด | รายละเอียด |
|---|---|---|
| NFR-01 | Usability | ส่วนติดต่อผู้ใช้ทั้งหมดเป็นภาษาไทย ออกแบบให้ใช้งานง่ายสำหรับผู้สร้างคอนเทนต์ทั่วไปที่ไม่มีพื้นฐานด้านเทคนิค |
| NFR-02 | Performance | หน้าเว็บหลักต้องแสดงผลสมบูรณ์ภายใน 3 วินาที ภายใต้การเชื่อมต่ออินเทอร์เน็ตปกติ |
| NFR-03 | Security | รหัสผ่านต้องเข้ารหัสด้วย bcrypt ก่อนบันทึก และทุกคำขอ API ต้องตรวจสอบสิทธิ์ผู้ใช้ผ่าน Session ก่อนเข้าถึงข้อมูล |
| NFR-04 | Availability | ระบบต้อง deploy บนโครงสร้างพื้นฐานที่รองรับการเข้าถึงได้ตลอด 24 ชั่วโมง 7 วัน |
| NFR-05 | Cost | ระบบในรุ่น MVP ต้องพัฒนาและใช้งานได้โดยไม่มีค่าใช้จ่าย โดยใช้ Free Tier ของผู้ให้บริการทุกตัว |
| NFR-06 | Compatibility | รองรับการแสดงผลแบบ Responsive บนคอมพิวเตอร์และอุปกรณ์พกพาผ่านเว็บเบราว์เซอร์ |
| NFR-07 | Maintainability | โครงสร้างโค้ดต้องแยกส่วน UI, API และการเชื่อมต่อฐานข้อมูลอย่างชัดเจน เพื่อให้แก้ไขและต่อยอดได้ง่าย |

## 7. สถาปัตยกรรมและเทคโนโลยีที่ใช้ (Technology Stack)

| องค์ประกอบ | เทคโนโลยีที่ใช้ |
|---|---|
| Frontend / Backend Framework | Next.js 14 (App Router), React, Tailwind CSS |
| ระบบยืนยันตัวตน (Authentication) | NextAuth.js — Credentials Provider, GitHub OAuth, Google OAuth |
| ฐานข้อมูล (Database) | Supabase (PostgreSQL) |
| บริการ AI | Google Gemini API (โมเดล gemini-3.6-flash) สำหรับสร้างไอเดียคอนเทนต์ |
| การจัดเก็บซอร์สโค้ด | GitHub |
| การ Deploy / Hosting | Vercel (Free / Hobby Tier) |

## 8. ข้อจำกัดและสมมติฐาน (Constraints & Assumptions)

- ระบบทั้งหมดพัฒนาและใช้งานอยู่บน Free Tier ของผู้ให้บริการ (Vercel, Supabase, Google AI Studio) จึงมีข้อจำกัดด้านโควตาการใช้งานตามเงื่อนไขของผู้ให้บริการ
- การสร้างไอเดียด้วย AI ขึ้นอยู่กับความพร้อมใช้งานของ Gemini API ซึ่งอาจมีความล่าช้าในช่วงที่มีผู้ใช้งานจำนวนมาก
- ระบบไม่ได้เปิดใช้งาน Row Level Security (RLS) ของฐานข้อมูล โดยการตรวจสอบสิทธิ์ทั้งหมดดำเนินการที่ชั้น API แทน
- ผู้ใช้ต้องมีการเชื่อมต่ออินเทอร์เน็ตตลอดการใช้งาน เนื่องจากเป็นระบบที่ทำงานผ่านเว็บเบราว์เซอร์ทั้งหมด

---

## 9. เกณฑ์การยอมรับของ MVP (Acceptance Criteria)

- ผู้ใช้สามารถสมัครสมาชิกและเข้าสู่ระบบได้ครบทั้ง 3 ช่องทางโดยไม่เกิดข้อผิดพลาด
- ระบบสามารถสร้างไอเดียคอนเทนต์จาก AI ได้สำเร็จภายใน 1 นาทีต่อการร้องขอ 1 ครั้ง (ภายใต้สภาวะปกติ)
- ผู้ใช้สามารถสร้าง แก้ไข เปลี่ยนสถานะ และลบงานคอนเทนต์ได้ครบทุกฟังก์ชันโดยข้อมูลถูกบันทึกลงฐานข้อมูลอย่างถูกต้อง
- ระบบสามารถ deploy และเข้าถึงได้ผ่านโดเมนสาธารณะตลอด 24 ชั่วโมงโดยไม่มีค่าใช้จ่าย
